## Purpose

由平台自己分发接入所必需的探针物料（JaCoCo agent 与三种语言的探针源码），使内网环境下的用户无需访问外网、也无需翻仓库就能拿到它们，并保证拿到的版本与平台解析覆盖数据时用的版本一致。

## Requirements

### Requirement: 平台分发探针物料

系统 SHALL 提供接口，交出接入所需的探针物料：JaCoCo agent，以及 Go、C++、Rust 三种语言的探针源码文件。物料 SHALL 随平台自身的构建产物一同分发，不依赖平台运行时所在机器的源码目录，也不依赖任何外网地址。

#### Scenario: 下载 JaCoCo agent

- **WHEN** 用户请求 Java 的探针物料
- **THEN** 系统交出可直接用于 `-javaagent` 的 JaCoCo agent 文件

#### Scenario: 下载某语言的探针源码

- **WHEN** 用户请求 Go、C++ 或 Rust 的探针物料
- **THEN** 系统交出该语言对应的探针源码文件，内容与平台随附的那一份逐字一致

#### Scenario: 部署环境没有源码目录时仍可下载

- **WHEN** 平台部署在一台没有本项目源码的机器上
- **THEN** 探针物料照常可下载

#### Scenario: 不依赖外网

- **WHEN** 平台所在网络无法访问外部网络
- **THEN** 探针物料照常可下载

### Requirement: 分发的 agent 版本与平台解析所用版本一致

系统分发的 JaCoCo agent 版本 SHALL 与平台归一化覆盖数据时所用的 JaCoCo 版本相同。系统 SHALL 让用户可以看到所分发物料的版本。

#### Scenario: 版本对用户可见

- **WHEN** 用户查看 Java 的探针物料
- **THEN** 页面标明该 agent 的版本
- **AND** 该版本即平台用于解析 exec 数据的版本

### Requirement: 说明物料的适用前提

系统 SHALL 在提供下载处写明每份物料成立的前提条件，使不满足前提的用户在下载前就能知道它接不上，而不是接完发现没有数据再来排查。

#### Scenario: Go 探针的同包前提

- **WHEN** 用户查看 Go 探针物料
- **THEN** 说明指出该探针需与被测服务的 `main` 包同包、并由构建标记守卫
- **AND** 说明指出被测服务不是可执行程序（如库工程）时该探针不适用

#### Scenario: C++ 与 Rust 探针的链接前提

- **WHEN** 用户查看 C++ 或 Rust 探针物料
- **THEN** 说明指出该探针需作为独立编译单元参与链接，以及它对构建方式的要求

### Requirement: 物料下载是只读操作

获取探针物料 SHALL NOT 改变任何项目配置、覆盖数据、场景状态或采集行为。

#### Scenario: 下载不影响正在进行的采集

- **WHEN** 用户在平台正常采集期间下载探针物料
- **THEN** 覆盖数据与采集节奏不受影响
- **AND** 项目配置不发生变化
